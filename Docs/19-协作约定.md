# 协作约定（必须遵守）

## 1. 技术路线变更必须先问

**任何会改变实现方式的决定，动手前必须先征求确认。** 包括但不限于：

| 类型 | 例子 |
| --- | --- |
| 删除/替换资源 | 删掉预制体让代码接管渲染 |
| 架构切换 | 代码构建 ↔ 预制体构建、同步 ↔ 事件驱动 |
| 引入新依赖 | 第三方包、新的数据结构 |
| 改变数据来源 | 表驱动 ↔ 代码写死 |
| 大范围重构 | 一次性改动多个核心文件 |

违反过的一次：在没有询问的情况下删除了 `Resources/UI/CardView.prefab`，
把卡牌从「预制体驱动」改成「代码生成」。已回退。

## 2. 配置表不主动改

`DataTables/*.xlsx` 只读。需要改时先说明改哪张表、哪一列、改成什么，确认后再动。

## 3. 回退优先于补救

一旦发现某次改动影响了既有实现，先回退到改动之前的状态，再讨论新方案。
不要在错误的基础上继续叠加修改。

# 卡牌渲染架构（当前）

```
Resources/UI/CardView.prefab     ← 结构：层级、坐标、文字（可手动编辑）
        ↓ 运行时实例化
CardView.Initialize()
        ├─ EnsureFont()          ← 字体
        └─ ApplySkin(face)       ← 按节点名注入部件精灵
             Frame / Banner / CostBadge / TypeChip / DescPanel
```

**为什么要运行时注入**：部件精灵由 `CardSkin` 用 `Sprite.Create` 在运行时生成，
不是工程里的图片资产，**无法序列化进预制体**（存进去会变成空引用）。

所以职责划分是：

- **预制体**：管结构（节点名、坐标、尺寸、文字内容）
- **代码 `ApplySkin`**：管皮肤（贴哪张图、九宫格边框粗细）

修改预制体时注意：**节点名不能改**，`ApplySkin` 靠名字找节点。
