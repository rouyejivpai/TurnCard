# 协作约定（必须遵守）

## 1. 技术路线变更必须先问

**任何会改变实现方式的决定，动手前必须先征求确认。** 包括但不限于：

| 类型 | 例子 |
| --- | --- |
| 删除/替换资源 | 删掉预制体让代码接管渲染 |
| 架构切换 | 代码构建 ↔ 预制体构建、同步 ↔ 事件驱动 |
| 引入新依赖 | 第三方包、新的数据结构 |
| 改变数据来源 | 表驱动 ↔ 代码写死 |
| 大范围重构 | 一次性改动多个核心文件 |

把卡牌从「预制体驱动」改成「代码生成」。已回退。

## 2. 配置表不主动改

`DataTables/*.xlsx` 只读。需要改时先说明改哪张表、哪一列、改成什么，确认后再动。

## 3. 回退优先于补救

一旦发现某次改动影响了既有实现，先回退到改动之前的状态，再讨论新方案。
不要在错误的基础上继续叠加修改。

# 卡牌渲染架构（当前）

```
Resources/UI/CardView.prefab     ← 结构：层级、坐标、文字（可手动编辑）
        ↓ 运行时实例化
CardView.Initialize()
        ├─ EnsureFont()          ← 字体
        └─ ApplySkin(face)       ← 按节点名注入部件精灵
             Frame / Banner / CostBadge / TypeChip / DescPanel
```

**为什么要运行时注入**：部件精灵由 `CardSkin` 用 `Sprite.Create` 在运行时生成，
不是工程里的图片资产，**无法序列化进预制体**（存进去会变成空引用）。

所以职责划分是：

- **预制体**：管结构（节点名、坐标、尺寸、文字内容）
- **代码 `ApplySkin`**：管皮肤（贴哪张图、九宫格边框粗细）

修改预制体时注意：**节点名不能改**，`ApplySkin` 靠名字找节点。

# 界面架构（当前）

流程界面（主菜单 / 地图 / 营地 / 奖励 / 商店 / 结算 / 牌组列表 / 牌堆列表）**全部是预制体**，
路径统一在各界面的 `ResourcePath` 常量里：

```
Resources/UI/Flow/MenuScreenWindow.prefab
Resources/UI/Flow/CardGridScreenWindow.prefab
Resources/UI/Flow/CardListViewScreenWindow.prefab
        ↓ FormHost.Open(ResourcePath) 实例化
MenuScreen（partial : UIBindWindow）
        ├─ MenuScreen.Components.cs      ← UIBind 生成：字段 + InitComponents + OnCreate
        └─ AddButton()                   ← 克隆预制体里的 btnTemplate，不在代码里造按钮
```

对应生成器：`Tools/TurnCard/生成流程界面预制体`（`Editor/FlowPrefabBuilder.cs`）。
校验器：`Tools/TurnCard/校验流程界面预制体`（`Editor/FlowPrefabCheck.cs`）。

改布局只改预制体，**不要**再往代码里写 `CreateBox / CreateLabel` 拼界面。

## 三条硬约束

1. **节点名 = 生成的变量名**（`txtTitle` / `goButtons` / `btnTemplate` …）。
   改节点名必须重跑生成器，否则绑定脚本里的字段名对不上。
2. **生成器不覆盖手写脚本**。UIBind 自带的 `CreateUIScript` 会把正常脚本整个重写成模板，
   所以生成器只写 `<类名>.Components.cs`；基类 `UIBindWindow` 声明在手写脚本里，
   保证「先改脚本、后跑生成器」的中间状态也能编译。
3. **绑定数量必须等于预期**，否则生成器拒绝写脚本（写出去会变成一堆「找不到字段」的编译错误）。

## 预制体里允许留的「代码布局」

- 卡牌/敌人/Buff 图标的**摆放坐标**（数量运行期才知道）
- 特效弹道、飘字、光边（逐帧参数）
- 这些只算「按数据算位置」，容器与模板仍然必须在预制体里。

## 编辑器注意

- 当前打开的预制体隔离舞台会挡住生成器/截图，生成前先回到主舞台。
- `UIBindMono.PrefabInfo` 不参与序列化，`PrefabUtility.LoadPrefabContents` 打开的对象
  解析不出路径，`OnEnable` 会让它自毁 —— 生成器用「先失活再挂组件」绕开，
  别在别处直接 `LoadPrefabContents` + `AddComponent<UIBindMono>`。
