# 01 原始需求

本篇是**唯一的需求事实来源**。下面第 1 节照录原始表述，第 2 节逐条拆解，
第 3 节指出需求内部尚未闭合的地方。任何规则文档都不得超出本篇与问答台账的结论。

## 1. 需求原文

> 以下是项目的原始需求，本游戏的核心特点是翻转卡牌，每张卡都有正反两面，战斗流程类似杀戮尖塔，
> 底层规则的主要区别是，卡牌使用后会反转而非进入弃牌堆（使用的交互方式，无目标卡牌点击使用，
> 有目标卡牌拖拽使用，拖拽时卡牌轻微上浮且拉出箭头），游戏构图类似骰子浪游者，敌人在正前方，
> 手牌区在正下方，左下抽牌堆，右下弃牌堆。敌人看起来也是一张卡牌，但和一般的卡牌形式不同，
> 敌人卡的左下角显示攻击力，右下角显示血量，有正反两面，也就是敌人的两种形态（切换条件默认为血量归零）。
> 卡牌翻转是游戏的核心特色，所以必须要有卡牌翻转的动画。

## 2. 逐条拆解

| 编号 | 原文要点 | 可落地的事实（不含推测） |
| --- | --- | --- |
| R1 | 每张卡都有正反两面 | 卡牌数据至少需要「正面」「背面」两套表现 |
| R2 | 战斗流程类似杀戮尖塔 | 回合制战斗；具体沿用哪些机制未说明 |
| R3 | 卡牌使用后会反转，而非进入弃牌堆 | 「翻转」是使用卡牌的后果，且这句话把「翻转」与「进弃牌堆」对立起来 |
| R4 | 无目标卡点击使用；有目标卡拖拽使用 | 卡牌分「需要目标」与「不需要目标」两类，操作方式不同 |
| R5 | 拖拽时卡牌轻微上浮并拉出箭头 | 拖拽态需要位移与指向可视化 |
| R6 | 构图类似骰子浪游者：敌人正前方、手牌正下方、左下抽牌堆、右下弃牌堆 | 四个固定区域 |
| R7 | 敌人也是一张卡牌，但形式不同 | 敌人共用卡牌载体，但版面布局与普通卡不同 |
| R8 | 敌人卡左下角显示攻击力，右下角显示血量 | 敌人卡面有两个固定数值位 |
| R9 | 敌人正反两面即两种形态，切换条件默认为血量归零 | 敌人有两个形态；触发切换的条件可配置，默认值与血量相关 |
| R10 | 卡牌翻转必须有动画 | 翻转是核心体验，动画是必需项而非可选 |

## 3. 需求内部的张力

以下四点不解决就无法写实现，已转为问答台账中的问题：

1. **R3 与 R6 冲突**：如果卡牌使用后是翻面而不是进弃牌堆，那「右下角的弃牌堆」收的是什么？
   两者并存，说明「翻转」与「弃置」是两套并行的处理，但触发条件未定义。（→ Q2）
2. **R1 未定义背面是什么**：每张卡都有两面，但背面是「另一个效果」还是「已使用的状态」，
   差别极大——前者是双重效果的设计空间，后者只是资源冷却。（→ Q1）
3. **R9 的「默认」**：既说默认为血量归零，说明该条件可变；但翻面之后血量如何、
   何时真正死亡，完全没有定义。（→ Q3）
4. **R2 的「类似」**：可以只指「回合制出牌」这一层，也可以包含能量、抽牌堆、护甲、
   敌人意图等一系列机制。范围不界定，工作量差一个数量级。（→ Q4）
