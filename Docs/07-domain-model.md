# 07 领域模型：卡牌、面与翻面

状态：由 Q14 的结论整理而来。这是实现层的骨架，规则变化时优先修改这里，再改代码。

## 1. 核心抽象

整个游戏只有一个核心动作：**翻面（Flip）**。

- 一张卡有且只有两面，任意时刻只有一面朝上。
- 翻面 = 把当前面换成另一面，是一个与具体业务无关的原子操作。
- 触发翻面的原因是多样的：使用卡牌、角色卡当前形态血量归零、卡牌效果强制翻转……
  这些**都不改变翻面本身的语义**，只是调用方不同。

这条抽象否定了「敌人形态切换」作为独立机制的存在：敌人血量归零时发生的，
与玩家打出一张牌时发生的，是同一件事。

## 2. 类型层次

```
CardDefinition（所有卡牌的基类）
├── 两面：front、back
└── 每面各自持有：名称、描述、费用、类型、效果

CharacterCardDefinition : CardDefinition（角色卡）
└── 额外持有：每一面的攻击力、每一面的生命上限
```

- **角色卡**是「带攻击力与生命」的卡牌类型（Q14）。
- **敌人是角色卡的实例**，被摆到战场正前方的区域。
- 普通手牌是卡牌实例，不需要攻击力与生命。

## 3. 运行时实例

每张卡在运行时至少携带：

| 字段 | 说明 |
| --- | --- |
| `definition` | 指向卡牌定义（静态数据） |
| `currentFace` | 当前朝上的是正面还是背面（Q16 决定它在战斗内持久） |
| `zone` | 当前所在区域：抽牌堆 / 手牌 / 弃牌堆 / 战场 |
| `currentHp` | 仅角色卡：当前形态的剩余生命 |
| `currentArmor` | 仅角色卡：护甲（若该角色使用护甲） |

`Flip()` 只做一件事：切换 `currentFace`，并播放翻转动画。它不负责判定死亡、
不负责扣除生命、也不清理状态。判定与结算由调用方在翻面前后完成。

## 4. 结算顺序（以敌人血量归零为例）

1. 攻击牌对敌人造成伤害。
2. 生命值扣到 0 或以下。
3. 判定：该角色是否还有未使用的形态？
4. 有 → 调用 `Flip()`，`currentHp` 重置为背面形态的生命上限。
5. 无 → 该角色死亡，从战场移除。

第 4 步中「重置为背面形态的生命上限」是 Q3（第二形态满血重开）的直接要求；
翻面本身不负责重置生命，这是调用方（战斗流程）的职责。

## 5. 玩家不在这个模型里

玩家**不是卡牌**（Q30）：目前只有血条，没有正反面，也不参与翻面。
因此 `CharacterCard` 这一支只描述战场上的敌人，玩家用独立的轻量实体表示。

这条边界要守住：如果以后让玩家也变成卡牌，改动面会很大，届时应作为一次显式的设计变更。
