# 24 舞台流程（同一场景内跑完整流程）

状态：**已实现并跑通**（占位美术）

## 0. 实测结果

| 步骤 | 结果 |
| --- | --- |
| 主菜单「开始新游戏」 | **不再进地图界面**，直接开战斗界面并显示路线选项（1~3 个） |
| 路线选项 | 从「普通战斗 / 精英战斗 / 火堆 / 商店」里随机抽 1~3 个 |
| 点「精英战斗」 | 用 Elite 池开战（实测抽到「舞台布景」），`RouteStep` +1 |

| 0.5s 后 | `CardGridScreen` 弹出，3 张牌、`ChoiceMode=True`（可点），**宝箱仍留在屏幕上** |
| 选一张 | 选卡界面关闭、金币/加牌生效、舞台区重新出现路线选项 |
| 点「火堆」 | 回复 30% 最大生命（实测 40→64），提示文字显示回复量，然后重抽路线 |

## 1. 目标

所有流程表现都在**同一个场景**（现在的 Battle 场景）里完成，不再切场景、不再切整屏界面。
舞台区是一块可替换内容的区域：

```
选关    → 1~3 个路线节点（普通战斗 / 精英战斗 / 火堆 / 商店）
战斗    → 敌人卡
胜利    → 宝箱（关闭态）→ 点击 → 打开态 → 0.5s → 选卡奖励（全屏浮层）
选完    → 舞台区重新显示路线节点
```

## 3. 关键结构问题（已解决）

`ProcedureBattle.OnLeave` 里会 `UIHost.Shared.Close(form)` —— 切到 ProcedureReward 时 BattleForm 就被销毁，
舞台区随之消失。所以现在的做法是：**胜利后不离开 ProcedureBattle**，由 BattleForm 自己走完
「宝箱 → 选卡 → 路线」，点完路线就**在同一界面重开下一场**：

```
state.BattleEnded(victory)
   ├─ 失败 → ShowResultDelayed(false) → BattleFinishedEvent(false) → ProcedureGameOver
   └─ 胜利 → BeginVictoryFlow()
             → StageView.ShowChest(OnChestOpened)
                → 玩家点宝箱 → 打开态 → FlowSettings.ChestOpenDelay(0.5s)
                   → CardGridScreen（全屏浮层，宝箱仍在）
                      → 选牌（金币 + Run.AddCard）→ 关浮层
                         → StageView.ShowRoutes(3, onPick)
                            → 点选项 → RestartBattle()（清手牌 + 重建 BattleState）
```

> **注意**：现在 `ProcedureReward` 不再被走到（胜利不再发 `BattleFinishedEvent`）。
> 首领/通关等分支要等「路线选项接真实地图数据」时再接回流程。

### 舞台区的搭建方式（重要）

这个窗口的绑定是 **UIBind 索引式**（`BattleFormWindow.prefab` 里没有 UIBindMono/BattleForm 组件，
运行时由 `UIBindWindow` 补），手工用 `LoadPrefabContents` 改预制体会**打断绑定**
（表现是 `txtResult` 变 null、胜利面板 NRE）。

所以 `StageArea` 由 `BattleForm.EnsureStage()` **在运行时搭**：
以 `EnemyArea` 的矩形为准，建 `StageArea` → `goChest` / `goRoutes`。
宝箱与路线选项本身仍是预制体（`Resources/UI/Stage/*`），美术替换图即可。

> 以后若要把舞台区正式做进预制体，**必须在 UIBind 编辑器里操作**，不要用脚本改这个 prefab。
