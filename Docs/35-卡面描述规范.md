# 35 · 卡面描述规范

描述（`Cards.xlsx` 的 `frontDescription` / `backDescription`）要遵守下面几条，
保证同类效果的写法一致、数值能在战斗里实时更新。

## 1. 「每有一张 …」类动态数值

**写法**：`手牌中每有一张<对象>，<效果>一次（共 {total_x} 点）`

| 例子 | 文案 |
| --- | --- |
| 自愈 | 手牌中每有一张状态牌，获得 5 点格挡一次（共 {total_armor} 点） |
| 全力一击 | 手牌中每有一张牌，造成 4 点伤害一次（共 {total_damage} 点） |
| 佯攻 | 回合结束时，手牌中每有一张状态牌获得 2 点格挡（共 {total_armor} 点） |
| 死斗 | 手牌中每有一张状态牌，获得 1 点**临时力量**（共 {total_strength} 点） |
| 力降十会 | 使手中前 X 张状态牌翻面，每张获得 5 点护甲（共 {total_armor} 点） |

要点：

- **先写「一次」的单次效果，再在括号里给总量** —— 玩家先理解规则，再看当前值。
- 括号统一用**全角**「（共 X 点）」，与卡面其它括号保持一致。
- 总量 token 必须由效果提供（见第 3 节），否则会退化成单次值。

## 2. X 的两种含义

| 写法 | 含义 | 例子 |
| --- | --- | --- |
| 直接写 `X` | X = **剩余费用**（`params.xcost`），卡面/描述都**不做数值替换** | 力降十会「前 X 张」 |
| 写 `{x}` | X = **数量**（手牌数 / 状态牌数），战斗中显示真实数字 | ！不公！「（当前 {x}）」 |

## 3. 总量 token 一览

| token | 由谁提供 | 说明 |
| --- | --- | --- |
| `{total_damage}` | `damage_times` / `damage_times_adjacent_status` | 单次伤害 × 次数 |
| `{total_armor}` | `armor_times` / `armor_per_status` | 单次护甲 × 次数 |
| `{total_strength}` | `temp_strength` | 临时力量总量 |
| `{total_damage_max}` | `damage_times_adjacent_status` | 触发条件时的上限（暂未上卡面） |

拿不到上下文时（牌库、商店等非战斗界面），`{total_damage}/{total_armor}` 退回单次值，
`{total_strength}` 等其它 token 会退回卡面 `params` 里的同名字段。

## 4. 数值染色

卡面数字和「基础值」不同时自动标红（`CardView.SetValuePreview` → `m_PreviewDamage`），
描述里不用手写颜色。

## 5. 改写检查清单

1. 效果串里的次数/总量是否都由效果自己提供 token？（第 3 节）
2. 描述里的 `{x}` 是数量还是费用？费用必须写 `X`。
3. 括号里给的是不是**总量**而不是单次值？
4. 改完 `DataTables/Cards.xlsx` 后跑 `Tools/TurnCard/数据表/生成 SO`，再进战斗看实际文案。
