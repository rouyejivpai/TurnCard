# 28 · 响应式数据流（MVVM）

战斗界面的刷新不再由业务代码「记得去推」，而是数据一变就自动重绘。

## 分层

```
Model        BattleState / EnemyInstance / CardInstance
             只算规则与数值；任何数值变化都抛事件
   ↓ 事件
ViewModel    BattleViewModel
             把模型数值换算成「UI 直接能用的快照」，不碰任何 UI 对象
   ↓ 快照
View         BattleForm / EnemyCardView / CardView
             只做「快照值 → 控件」的写入
```

## Model：可观察的数值

| 对象 | 事件 | 触发时机 |
| --- | --- | --- |
| `EnemyInstance` | `HpChanged` | 受伤、**回血**、翻面重置血量 |
| `EnemyInstance` | `ArmorChanged` | 护甲增减/清零 |
| `EnemyInstance` | `IntentChanged` | 意图选定/推进/重洗 |
| `EnemyInstance` | `Buffs.Changed` | buff 增删层数 |
| `BattleState` | `PlayerHpChanged` / `PlayerArmorChanged` / `EnergyChanged` | 玩家数值 |
| **`BattleState`** | **`Changed`** | 以上所有事件的汇总口，UI 只需要听这一个 |

> 关键点：以前 `EnemyInstance.Heal()` 只改字段、不发声，所以「自愈」回血后血条要等下一次受伤才更新。
> 现在 `Hp` 是带 setter 的属性，**任何**写入都会触发 `HpChanged`。

## ViewModel

`BattleViewModel.Update(state, hoverTarget)` 一次算出：

```csharp
PlayerHp / PlayerHpMax / PlayerHpRatio / PlayerArmor / Energy / MaxEnergy
Enemies[] { Enemy, HpRatio, HpText, Armor, ArmorVisible, IntentValue, IntentModified }
Hand[]    { Card, Damage, Armor, Modified, Tokens }
```

- 意图数字、手牌预览、血条比例都在这里算好，**视图层不再自己调 `PreviewXxx()`**。
- 拖牌指着敌人时把 `hoverTarget` 传进来，手牌伤害就会算上该目标的易伤。

## View：脏位 + 帧末合并

```csharp
state.Changed += MarkRenderDirty;      // 唯一的订阅
void Update() { if (dirty) FlushRender(); }
void FlushRender() { vm.Update(...); ApplyPlayerHud(); ApplyEnemyViews(); ApplyHandViews(); }
```

- 同一帧内无论触发多少次事件，只渲染一次。
- 旧的 `RefreshHud()` / `RefreshAllHpBars()` 保留为**标脏**别名，老调用点语义不变（不再直接写控件）。

## 实测

| 场景 | 结果 |
| --- | --- |
| 直接 `enemy.Heal(5)`（不调用任何刷新） | 下一帧血条文字从 `12/18` 自动变成 `17/18` |
| 受伤 | 同帧标脏、下一帧刷新，与模型一致 |
| 回合推进（狼人攻击 9） | 玩家 80→71、敌人 25/25，血条与文本都正确 |

## 后续可复用

- 想要"血条缓动掉血"，在 `ApplyPlayerHud` / `ApplyEnemyViews` 里改成「目标值变化才启动补间」即可，不需要再动业务代码。
- 新界面（商店、营地）也可以复用 `BattleViewModel` 的写法：模型抛事件、VM 出快照、View 只写控件。
