# 卡面文本与关键词

## 0. 两套东西，别混

| 东西 | 位置 | 作用 |
| --- | --- | --- |
| **机制 tag** | Cards 表 `frontKeywords` / `backKeywords` | 驱动规则（瞬发、保留、光环…） |
| **显示关键词** | Keywords 表（名字 + 说明） | 决定描述里哪些词加粗、悬停弹什么说明 |

tag 可以是关键词（`瞬发`），也可以只是这张牌自己的机制（如光环 `双重瞬发`）——
**不在 Keywords 表里的 tag 不会加粗、也不弹提示**。

## 1. 三种写法

写在 `Cards.xlsx` 的 `frontDescription` / `backDescription` 列里：

| 写法 | 效果 |
| --- | --- |
| `**关键词**` | 加粗；**只有当它同时出现在关键词表里时**，悬停才会弹说明 |
| `*文字*` | 斜体，用于风味描述 |
| `{名字}` | 数值占位符，渲染时按当前面实时取值 |

占位符可用：`{name}` `{cost}` `{damage}` `{armor}`，以及 `frontParams` / `backParams` 列里自定义的键
（params 写 `dmg=3`，文本里就能用 `{dmg}`）。

> **提示栏只认加粗的词。** 没加粗就等于没写关键词：既不弹提示，也不加粗。
> 加粗了但不在关键词表里的词（比如 `**双管**`）只会加粗，不弹提示——可以用来强调卡名。
>
> 旧写法 `[[瞬发]]` 仍然兼容（等同于 `**瞬发**`），但新内容建议统一用 `**...**`。


## 2. 关键词表

`DataTables/Keywords.xlsx`：

| 列 | 含义 |
| --- | --- |
| `id` | 唯一编号 |
| `displayName` | 关键词名（必须和卡面 `[[...]]` 里的字完全一致） |
| `description` | 说明文本，**也可以带同样的标记** |

> 注意列名是 `displayName` 而不是 `name`：`m_Name` 是 Unity 对象自带的字段，会把自定义字段顶掉。

## 3. 悬停行为

鼠标移到卡牌上时：

- **立即**在卡牌左侧竖排弹出该卡当前面提到过的所有关键词（一个词一个框，框内是「词名 + 说明」）；
- 关键词说明里如果又提到别的关键词（`[[翻面]]`），会**递归展开**也列出来；
- 去重、按首次出现顺序、**最多 5 个**、循环引用自动跳过；
- 左侧放不下（贴屏幕边）会自动翻到卡牌右侧；
- 0.8 秒后右侧照常弹出「翻面后」的大卡预览，两者并存。

提示框是预制体：`Assets/Game/Resources/UI/KeywordTip.prefab`，
由 `Tools/TurnCard/生成关键词提示预制体` 生成，改样式直接改这个预制体。

## 4. 示例：火炮

表里这样写：

| 面 | 名称 | 费用 | 类型 | 效果 | 描述 |
| --- | --- | --- | --- | --- | --- |
| 正面 | 装填 | 1 | Skill | （空） | `装填。*它需要先装填。*` |
| 背面 | 开火 | 1 | Attack | `damage:3,random` | `[[瞬发]] 随机对一个敌人造成 {damage} 点伤害。` |

实战流程：打出「装填」（什么都不做）→ 卡牌翻到「开火」→ **瞬发**在翻面瞬间触发，
随机对一名敌人造成 3 点伤害。

**瞬发** 是内建关键词，语义写死在 `BattleState.TriggerInstant`：
卡牌翻到带 `[[瞬发]]` 的那一面时，再执行一次这一面的效果（有深度保护，防两面互触发）。

## 5. 加新关键词

1. 在 `Keywords.xlsx` 加一行名字与说明；
2. 在卡面文本里用 `[[名字]]`；
3. 如果这个关键词只是**说明性**的（不影响规则），到此为止；
4. 如果它有**机制含义**，需要在代码里实现（例如瞬发那种），告诉我在哪触发。

## 6. 机制 tag（keywords 列）

**keywords 列是卡牌的机制标记（tag），不是显示关键词。** 描述文本只负责显示。

| tag | 效果 | 写在哪 |
| --- | --- | --- |
| `瞬发` | 卡牌翻到此面时，立即触发这一面的效果一次 | 该面的 keywords 列 |
| `保留` | 回合结束时这张牌不进弃牌堆，留在手上 | 该面的 keywords 列 |
| `双重瞬发` | 光环：此面朝上时，瞬发结算两次 | 该面的 keywords 列 |

例：火炮背面的 keywords 写 `瞬发`（机制），描述里写「瞬发 随机…」（显示）。

**校验**：`Tools/TurnCard/数据表/检查文本与效果` 会报出 keywords 列里写了但代码没实现的名字。

## 7. 光环型关键词（联动）

有些关键词是「此面朝上时持续生效」的光环，例如「双重瞬发：瞬发触发两次」。

加一个光环只要三步：

```csharp
[AuraKeyword("双重瞬发")]
public sealed class DoubleInstantAura : IAuraKeyword
{
    public int ModifyInstantRepeat(BattleState state, CardInstance owner)
    {
        return 1;   // 每次瞬发多触发一次
    }
}
```

1. 写实现类（放在 `Assets/Game/Scripts/Battle/Auras/`）；
2. `Keywords.xlsx` 加说明文字，供悬停显示；
3. 想让哪张卡拥有它，就在该卡的 keywords 列写 `双重瞬发`。

实测：手上同时有「火炮」和一张带「双重瞬发」的牌时，瞬发一次造成 6 点伤害（两个 3）。

## 8. 哪些牌需要选目标

不再看卡牌类型，而是看效果串：

| 效果 | 是否需要拖到敌人身上 |
| --- | --- |
| `damage:6` | 需要 |
| `damage:9,all` | 不需要（打全体） |
| `damage:3,random` | 不需要（随机选一个） |
| 只有 `armor` / `draw` / `heal` 等 | 不需要 |

这样「随机对一个敌人造成伤害」这类卡，玩家直接点击就会结算，不会被要求先拖一个目标。


## 6. 已知限制

- 关键词提示框会盖住相邻手牌（按规则就是「列在卡牌左侧」，中间位置的牌必然压到邻居）
- 描述用的是 TMP 富文本，人工写了 `<` `>` 会被当成标签
